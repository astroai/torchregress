## 2024-04-30 - Vectorized _pit_from_quantiles in metrics
**Learning:** PyTorch internal loops using `.item()` cause severe CPU-GPU synchronization bottlenecks. In this specific codebase (`src/torchregress/metrics/distribution.py`), the `_pit_from_quantiles` metric function was iterating row-by-row over tensors, causing unnecessary performance degradation for large batches.
**Action:** Replaced the loop with vectorized PyTorch operations like `torch.searchsorted`, `torch.gather`, and `torch.where`. This eliminates $O(N)$ Python loop iterations and Python-to-C++ context switches, demonstrating that core metric computations should always be purely vectorized in PyTorch.
## 2025-06-04 - PyTorch Device Synchronization Bottlenecks in Metric Loops
**Learning:** In PyTorch, using `.item()` to extract scalars from tensors inside Python loops (like iterating over quantiles or coverage levels) forces a CPU-GPU synchronization block at every iteration. This completely nullifies GPU acceleration advantages for metric computation. The `RiskCoverageCurve.compute` method was iterating over `coverage_levels` and calling `.item()`, making it a massive hidden bottleneck.
**Action:** When computing metrics across thresholds, levels, or bins, avoid scalar extraction (`.item()`). Instead, vectorize the operations completely using native tensor functions like `torch.round`, `torch.clamp`, and tensor indexing on the device.
