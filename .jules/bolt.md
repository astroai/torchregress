## 2024-04-30 - Vectorized _pit_from_quantiles in metrics
**Learning:** PyTorch internal loops using `.item()` cause severe CPU-GPU synchronization bottlenecks. In this specific codebase (`src/torchregress/metrics/distribution.py`), the `_pit_from_quantiles` metric function was iterating row-by-row over tensors, causing unnecessary performance degradation for large batches.
**Action:** Replaced the loop with vectorized PyTorch operations like `torch.searchsorted`, `torch.gather`, and `torch.where`. This eliminates $O(N)$ Python loop iterations and Python-to-C++ context switches, demonstrating that core metric computations should always be purely vectorized in PyTorch.
## 2024-05-14 - Vectorized ECE Calculation
**Learning:** Sequential loops inside metrics like `ExpectedCalibrationError.compute` that create tensors per-iteration introduce severe CPU-GPU synchronization bottlenecks in PyTorch. The `expected_calibration_error` methods were using a `for` loop over quantiles which dominated execution time.
**Action:** Replaced the `for` loop with a vectorized broadcast `(y_true.unsqueeze(0) <= preds).float().flatten(1).mean(dim=1)` which performs the exact same operation via C++/CUDA backend, yielding over a ~3-4x performance improvement. Always look for loops over hyperparameters in PyTorch metric methods and vectorize them.
## 2025-02-23 - Fast Conformal Interval Construction
**Learning:** In PyTorch, allocating explicit coordinate grids (e.g., `torch.arange()`) and running global `torch.where()` masks just to find the start and end of contiguous boolean blocks is extremely slow and memory-intensive, especially inside tight test-time inference loops.
**Action:** When finding the first and last `True` indices in a 1D or batched 2D boolean mask, use `.int().argmax(dim=-1)` for the first index, and `.flip(dims=[-1]).int().argmax(dim=-1)` for the last index (subtracting from the total size). This avoids explicit coordinate tensor creation and executes entirely in fast native reductions. Additionally, prefer using native Python scalars (like `float("inf")`) directly in `torch.where` over wrapping them in `torch.tensor(INF, device=...)` when filling bounding values, combined with `torch.amin`/`torch.amax(..., keepdim=True)`.
## 2025-06-04 - PyTorch Device Synchronization Bottlenecks in Metric Loops
**Learning:** In PyTorch, using `.item()` to extract scalars from tensors inside Python loops (like iterating over quantiles or coverage levels) forces a CPU-GPU synchronization block at every iteration. This completely nullifies GPU acceleration advantages for metric computation. The `RiskCoverageCurve.compute` method was iterating over `coverage_levels` and calling `.item()`, making it a massive hidden bottleneck.
**Action:** When computing metrics across thresholds, levels, or bins, avoid scalar extraction (`.item()`). Instead, vectorize the operations completely using native tensor functions like `torch.round`, `torch.clamp`, and tensor indexing on the device.
